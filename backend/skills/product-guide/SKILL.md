# AI Workspace 产品使用手册

本手册描述产品自身的操作方法与行为规则。回答用户提问时，只依据本手册的事实，不要推测未写明的行为。

## 一、产品定位

一个能查知识库、也能联网的 AI 工作区，三大能力：

| 能力 | 说明 | 实现方式 |
| --- | --- | --- |
| 知识库问答 | 基于用户上传的企业文档回答，带编号引用，来源卡片可展开核对、可下载原文 | RAG（检索增强生成）+ Chroma 向量数据库 |
| 天气查询 | 查任意城市当前或未来天气，真实数据不编造 | MCP 协议接入 Open-Meteo 服务 |
| 网页抓取 | 给一个网址，实时抓取页面内容后回答 | MCP 协议接入官方 fetch 服务 |

助手名叫**牛来**，性格沉稳可靠，始终称呼用户为"亮哥"，回答结论先行。

技术栈：FastAPI（后端）+ Next.js（前端）+ Chroma（向量库）+ DeepSeek（大模型）。

## 二、界面布局

左侧栏宽 240px，从上到下依次是：

1. **logo 区**：蓝色渐变圆形图标 + "AI Workspace" 文字
2. **【+ 新对话】按钮**：蓝色实心。回答生成过程中会禁用变灰，点不动是正常的
3. **"知识库"分区**：
   - 【上传文档】按钮：虚线边框，带回形针图标。上传过程中文字变成"上传中..."、鼠标变等待光标
   - 文件列表：每行显示 文档图标 + 文件名（过长会截断，鼠标悬停显示全名）+ 灰色小字"N片"（该文档被切成了多少个检索片段）
   - **下载和删除按钮默认隐藏，鼠标悬停到某一行才会出现**（下载图标在前、垃圾桶图标在后）
   - 库里没有文档时显示"暂无文档"
4. **"对话记录"分区**：会话按时间倒序排列（新会话在上），当前会话白底高亮，悬停出现删除按钮
5. **底部灰字**："RAG · FastAPI · Chroma · DeepSeek"

## 三、欢迎页与推荐问题

点【新对话】或首次打开时显示欢迎页：标题"嗨，我是牛来"，下面三张能力卡片（知识库问答 / 天气查询 / 网页抓取），再下面是 6 条推荐问题，**点一下就直接发送**：

- 年假几天？
- 公司代号是什么？
- 加班餐补怎么算？
- 北京现在天气怎么样？
- 帮我看看 example.com 页面的标题是什么

前三条演示知识库问答，中间两条演示 MCP 联网能力，最后一条演示人格设定。

## 四、知识库文档管理

### 上传

操作路径：左侧栏"知识库"分区 →【上传文档】→ 选择文件。

支持规则：

| 项目 | 限制 |
| --- | --- |
| 文件格式 | 只支持 `.txt`、`.md`、`.pdf`（文件选择框已过滤，其他格式选不到） |
| 文件大小 | 单个文件不超过 5MB |
| 文字量 | 提取出的文字不超过 30 万字（约 1000 个切片） |
| 切片方式 | 每片最多 300 字，相邻两片重叠 50 字 |
| 不支持 | 扫描件、图片型 PDF（没有文字层，产品不含 OCR 识别） |

两种特殊行为：

- **内容完全相同的文件禁止重复上传**。系统按文件内容算 MD5 指纹比对，所以**改个文件名再传也会被认出来**，提示里会告知库中已有的那个文件叫什么。
- **同名但内容不同 = 覆盖更新**。旧版本的切片会被清理干净，不会出现新旧两版同时被检索到的情况。

用户会看到的提示文案（原样，不要改写）：

- 成功：`上传成功：xxx（共 N 个切片）`
- 覆盖：`同名文件覆盖成功：xxx（旧版已清理，新版共 N 个切片）`
- 超大小：`文件太大（超过 5MB），请压缩或拆分后再上传`（前端会先预检当场提示，不用等网络往返）
- 格式不支持：`不支持的文件类型: .docx`
- 重复上传：`该文件已上传，禁止重复上传（库中已有内容完全相同的文件：xxx）`
- 文字太多：`文件文字内容过多（超过 30 万字），请拆分成多份上传`
- 扫描件：`未能提取到文字，可能是图片型/扫描件文件，暂不支持`
- 文件损坏或加密：`文件解析失败：文件可能已损坏、加密或格式异常，请检查后重新上传`
- 后端没启动：`上传失败：无法连接后端服务，请确认后端已启动`

### 删除

操作路径：文件列表某一行 → 悬停出现垃圾桶图标 → 点击 → 弹确认框。

确认框文案：`确定把「xxx」从知识库删除吗？相关切片会一并删除。`

删除会同时清掉两样东西：向量库里的全部切片 + 服务器上的原文件。

**「公司制度.txt」删不掉**，这是故意设计的。它是产品的演示样本文件，一旦被误删知识库就空了，所有 RAG 功能当场演示不出来。用户会看到：

`「公司制度.txt」是知识库的演示样本文件，不支持删除；需要更新内容时，上传同名文件即可自动覆盖旧版`

这个限制拦在后端接口上，所以绕过页面直接用 Postman、curl 调删除接口也一样删不掉。需要更新它的内容时，上传同名文件即可覆盖。

其他情况：库里没有这个文件时提示 `知识库中没有这个文件`。

### 下载

操作路径：文件列表某一行 → 悬停出现下载图标 → 点击。

下载得到的文件名是**用户当初上传时的原文件名**，不是服务器内部的名字（服务器上实际存的是"内容指纹+后缀"的形式，避免重名和中文编码问题）。

三种失败提示：

- `知识库中没有这个文件`
- `该文件为历史入库数据，未记录原文件，请重新上传`（早期版本入库的数据没有保存原文件）
- `服务器上的原文件已丢失，请重新上传`（记录还在但磁盘文件不见了）

## 五、回答里的引用编号与来源卡片

- 回答正文里的 `[1]`、`[2]` 标记表示这句话的依据来自哪份资料，编号从 1 开始
- 编号与回答下方的**来源卡片**严格一一对应，卡片显示文件名 + 原文片段，可以展开核对
- 卡片**先于正文出现**：不用等回答写完，出处就已经能看到了
- 卡片的出场门槛比"资料喂给模型"的门槛更严：相关性较弱的片段会给模型当背景参考，但不会出现在前台卡片里，避免用户看到无关出处

## 六、查不到内容时的表现

- 知识库里确实没有的内容，牛来会**如实说明没有相关资料，不会编造**公司制度
- 用户的口语化短句可能检索不到（比如接着上文只问"那餐补呢"），产品内置了一次**问题改写**：把口语短句补全成贴近文档措辞的完整问法再去检索
- 库里文档很少时，检索对措辞的敏感度会更高，建议用完整问法（例如"加班餐补怎么算？"比"那餐补呢"稳）

## 七、架构开关（演示者须知）

位置：`backend/app/config.py` 文件末尾三个开关。

| 开关 | 当前值 | 作用 |
| --- | --- | --- |
| `USE_LANGGRAPH` | `True` | 当前主力实现：流式打字机效果 + 引用卡片都齐全 |
| `USE_LANGCHAIN` | `False` | 打开后由 LangChain 框架接管工具调用循环，代价是**没有打字机效果**（整段回答一次性返回） |
| `USE_MCP` | `True` | 打开时加载天气和网页抓取两个外部工具服务；关掉就没有联网能力 |

三套实现的优先级：`USE_LANGGRAPH` > `USE_LANGCHAIN` > 手写版（两个开关都关时走纯 OpenAI SDK 的手写实现）。

两条必须知道的注意事项：

- **改完开关必须重启后端才生效**，热改无效
- MCP 工具加载失败时会**自动降级**：天气和网页抓取不可用，但知识库问答和闲聊照常工作，不影响服务启动

## 八、联网功能的使用细节

- **天气查询**：城市名建议用英文或拼音（如 `Beijing`），天气服务的地理编码对中文支持不稳定
- 问"明天天气怎么样"这类相对日期时，系统会先查当前时间再算日期（模型本身不知道今天是几号）
- **网页抓取**：要给完整网址（含 `http://` 或 `https://`）

## 九、回答用户提问的要求

1. **结论先行**：第一句直接给答案，再补细节
2. **给具体点击路径**：不要说"在侧边栏操作"，要说"左侧栏『知识库』分区的『上传文档』按钮"
3. **报错文案原样引用**：用户描述看到的提示时，用本手册里的原文核对，不要凭印象改写
4. **提醒隐藏交互**：下载和删除按钮要悬停才出现，用户找不到时先说这一点
5. **本手册没写的行为不要推测**：如实说明手册里没有这部分内容，不要编造产品功能
